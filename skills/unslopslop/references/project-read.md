# Project read and direction brief

Nothing is drawn before this page is filled. It takes five minutes and decides everything after it.

## 1. Read the project

Ask, or infer from what the user gave you (repo, copy, screenshots). Mark every inference as a guess and confirm the ones that change the direction.

| Question | Why it matters |
|---|---|
| What does the product do, in one sentence with a verb? | The first screen must show that verb happening |
| Who uses it, and in what state of mind? (rushed, curious, anxious, at play) | Sets mood, pace and density |
| On what device, in what light, for how long? | Mobile thumb zones, dark rooms, long sessions want calmer contrast |
| What medium? (web page, app screen, email, logo, motion, social post) | Picks the domain pack |
| Is a style asked for, or does one fit? | Picks a style pack, or none |
| What real content exists? (screens, photos, numbers with dates, quotes with names) | What can be shown; what must be a labelled placeholder |
| What must it never look like? (competitors, the user's own past attempts) | The rejected default |

## 2. Write the direction brief

```
Project:      <product, verb, audience, device>
Mood:         <three adjectives, e.g. calm, exact, warm>
Combination:  <2-4 colours with role and share, e.g. ink 70% ground, bone 22% text and paper, cobalt 3% action and paid state, grey 5% lines>
Type:         <display face + text face (free licence), sizes, one reason>
Texture:      <grain / pattern / watermark / light, where, opacity>
Depth:        <how surfaces stack: layered shadow, overlap, tones>
Motion:       <character (crisp, springy, slow), the one written moment, durations, reduced-motion behaviour>
Density:      <app dense / landing balanced / reading airy>
Signature:    <the one move only this product would make>
Rejected:     <the first default that came to mind and why it is out>
Domain/style: <packs to load>
References:   <2-3 ids from inspiration/catalog.md, at least one role:gold, each with what you take: e.g. "C10: product card on a photo, third layer crossing the edge"> (required)
Targets:      <from references/craft-recipes.md: display px, subject share of the first screen, layer order, ground/accent shares>
```

## 3. The generic-answer check

Before building, ask: if a plain prompt had solved this brief, where would it land? (purple gradient hero, three feature cards, beige serif document, glass cards). If your brief looks like that, change the part that matches and write down why.

## 4. Same product, different moods

A brief is right for a project, not in general. Write two alternative briefs in one line each before committing; if they differ only in colour, they are not alternatives (change layout family, type system or the main visual idea as well).
